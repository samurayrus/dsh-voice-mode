# dsh-voice-mode-ru

Русский форк [dsh-voice-mode](https://github.com/qishuilalala/dsh-voice-mode): тот же плагин голосового режима для DeepSeek Harness, но локальная озвучка переведена на **русский язык**.

Всё остальное — потоковое распознавание речи в черновик, автоотправка по паузе, перебивание голосом, субтитры — остаётся как в оригинале. Этот README описывает только то, что относится к русскому голосу.

## Что именно изменено

| Было в оригинале | Стало здесь |
|---|---|
| Kokoro `csukuangfj/kokoro-multi-lang-v1_1` (китайский + английский) | Kokoro [`zaakirio/kokoro-ru`](https://huggingface.co/zaakirio/kokoro-ru) (русский) |
| 103 китайских/английских голоса | 2 русских голоса: `masha` (по умолчанию), `sveta` |
| sherpa-onnx-node 1.13.6 | sherpa-onnx-node **2.0.1** + **espeak-ng** (G2P) |
| фронтенд фонем — lexicon внутри sherpa | свой воркер: espeak-ng (ru) → IPA → `phonemeCodepoints` |
| скачивание модели с проверкой SHA256 | модель готовится скриптом `scripts/prepare-ru-model.mjs` |
| настройки в `voice-mode.settings.json` | свой файл `voice-mode-ru.settings.json` |

Почему пришлось делать отдельный воркер: у Kokoro в sherpa-onnx нет espeak-фонемизации (фронтенд только lexicon), а версия 1.13.x молча игнорирует готовые фонемы. Поэтому текст фонемизируется снаружи, а в модель уходят уже готовые идентификаторы.

## Установка

Требуется **Node.js ≥ 18 в PATH**: движок Kokoro работает через нативный аддон, который не поднимается внутри Electron-хоста (при необходимости путь задаётся переменной `DSHVM_NODE`).

1. Установите плагин как обычно — через менеджер плагинов или зависимостью в профиле:
   ```
   dsh plugin add dsh-voice-mode-ru
   ```
2. Один раз скачайте модель (≈132 МБ, кладётся в кеш рядом с остальными моделями):
   ```
   node scripts/prepare-ru-model.mjs
   ```
   Скрипт идемпотентен: докачивает недостающее, собирает `tokens.txt` и `voices.bin`, дописывает в ONNX обязательные метаданные (`sample_rate`, `n_speakers`, `style_dim`, `speaker_names`, `has_espeak`).
3. Перезапустите DSH.
4. В настройках плагина: движок — **Local Kokoro**, голос — `masha` или `sveta`.

Важно: у плагина свои настройки, поэтому после установки он стартует с дефолтами (движок Edge). И не включайте его одновременно с оригинальным `dsh-voice-mode` — маршруты у них совпадают.

### Куда кладётся модель

```
Windows: %LOCALAPPDATA%\dsh-voice-mode\models\zaakirio\kokoro-ru
Linux/macOS: ~/.cache/dsh-voice-mode/models/zaakirio/kokoro-ru
```

Внутри — `model.onnx` (q8, ≈132 МБ), `voices.bin`, `tokens.txt`. Переопределить каталог: `node scripts/prepare-ru-model.mjs --dir <путь>`.

## Озвучка по команде: инструмент `say`

Оригинал читает вслух ответ целиком. Здесь добавлен инструмент `say`: агент сам решает, что произнести, а остальное остаётся текстом. Политика «когда и сколько говорить» записана в описании инструмента, поэтому действует в любой новой сессии.

Параметры: `text` (обязательный), `voice` (`masha`/`sveta`), `rate` (0.5–2). Вызов возвращается мгновенно — синтез идёт в фоне, звук приходит в браузер по мере готовности.

Под капотом — HTTP-маршрут `POST /voice-mode/say` с тем же поведением:

```json
{ "text": "Проверка связи", "voice": "masha", "rate": 1 }
```

Ответ приходит сразу: `{"ok":true,"accepted":true,"sentences":N}`. Кадры уходят клиенту через SSE с флагом `say: true` и синтетическим `sessionId: "__say__"`, поэтому озвучка работает даже при выключенном автоматическом чтении.

## Паузы и скорость

espeak выбрасывает знаки препинания из IPA, поэтому модель сама на них не останавливается — паузы вставляет воркер, а собственную тишину модели по краям обрезает, чтобы не было двойных провалов.

| Знак | Пауза |
|---|---|
| `,` | 150 мс |
| `;` `:` `—` `–` | 220 мс |
| `.` `!` `?` | 350 мс |
| `…` | 450 мс |
| конец фразы без знака | 250 мс |

Масштаб всего набора: переменная **`DSHVM_RU_PAUSE`** (0.1–3, по умолчанию 1). Скорость — параметр `rate` или настройка `rate` плагина.

## Настройки воркера

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DSHVM_RU_THREADS` | 4 | Потоки ONNX (1–8). При активном распознавании речи имеет смысл снизить до 2 |
| `DSHVM_RU_PAUSE` | 1 | Масштаб пауз по знакам препинания |
| `DSHVM_NODE` | — | Путь к настоящему Node ≥18, если его нет в PATH |

## Диагностика

```
GET  /voice-mode/models/status   → tts.engine, tts.local.repo, tts.local.ready
POST /voice-mode/preview         {"voice":"masha"} → WAV-проба речи
POST /voice-mode/say             {"text":"..."}    → принять фразу к озвучке
```

Ожидаемый ответ статуса: `tts.engine = "kokoro"`, `tts.local.repo = "zaakirio/kokoro-ru"`, `tts.local.files = []` (скачивать нечего — модель готовится скриптом).

## Ограничения

- **Ударения.** G2P — espeak без RUAccent: на специально подобранных «ударенческих» фразах около 27% WER против ~22% с RUAccent (замер автора модели). На обычных фразах разница почти незаметна.
- **Звук «л» и «р».** Для русского твёрдого «л» espeak выдаёт `ɭ`, которого нет в словаре модели; воркер подменяет его на `l`. Это самый слышимый дефект произношения.
- **Два голоса.** Мужского нет. `dima` существует, но на отдельном чекпойнте (`onnx/model_dima.onnx`, +≈138 МБ) — его можно добавить, расширив `voices.bin` и `n_speakers`.
- **Скорость.** RTF ≈ 0.9 на четырёх потоках (q8-модель, CPU).
- **Автономность.** Озвучка полностью локальная; распознавание речи тоже. Edge-движок в настройках остаётся облачным — если он выбран, текст уходит в Microsoft.

## Статус

Русский движок проверен отдельно: воркер синтезирует речь с паузами, инструмент и маршрут собираются в бандл. Проверка форка целиком в живом приложении (включая распознавание речи после перехода на sherpa-onnx-node 2.0.1) ещё предстоит.
